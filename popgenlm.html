PopGenLM Bench

I started PopGenLM Bench with 100 variants and a question I could test end to end: could I reproduce a genomic model’s scores and trace them back to the right alleles? Each release added a harder test. In v0.4, I ask whether adding a model score changes which linked variants I would follow up at an Arabidopsis expression locus.

The benchmark brings my population-genetics experience into the software itself, through reference checks, explicit score definitions, matched comparisons, and reproducible reports. Follow the learning story in Genomes to AI.

v0.5 · Development update · Evaluation in progress

Development staging · v0.4.0 remains the latest release

v0.5 extends the benchmark from variant prioritization to two separate questions: how sequence models rank Arabidopsis variants, and whether sequence-derived representations can predict measured gene expression or paired regulatory allele effects. The engineering work adds reference/alignment contracts, model-specific provenance, separately supervised expression heads, family-aware gene splits, shared metrics and CPU-recomputed figures. Sequence likelihood and conservation remain variant/conservation evidence; they are not expression. A supervised head is an additional trained predictor and is labelled separately from the underlying sequence model.

Every result on the inspected 300-gene set and the published v0.4 loci is development evidence. The expression set has already influenced implementation. The additional 600 genes remain reserved and unscored; they will be opened only after the complete preprocessing, model/checkpoint, metric and comparison protocol is frozen. New independent variant loci are a separate unfinished endpoint: the expression reserve cannot replace them. Held-out association-signal recovery is not causal-nucleotide validation.

What the engineering changed

I froze the accession split and candidate set before scoring, retained raw allele/strand definitions, and required each model and baseline to rank the same SNPs. That decision prevents coverage differences from becoming apparent model gains. Restartable shards, reference checks, checksum-pinned inputs and one shared evaluation implementation make the result inspectable beyond RAMSES. The gain and loss loci make the biological consequence visible. The result justifies transparent follow-up shortlists and independent tests; it does not identify causal nucleotides.

Why PopGenLM Bench is needed

Producing a score is an inference step. Establishing what that score means is an evaluation problem.

DNA language models learn statistical regularities from sequence context and can assign scores to large numbers of candidate variants. But a technically valid score is not automatically biological evidence. Before a score is interpreted, its coordinate system, alleles, reference sequence, model revision, orientation, provenance, statistical behaviour, and relationship to independent biological observations need to be checked.

Population and evolutionary genomics provide evidence against which model scores can be evaluated. PopGenLM Bench is designed as the reproducible layer between model output and biological claim: validate the inputs, preserve inference provenance, orient scores explicitly, quantify associations and uncertainty, and state what the result does — and does not — support.

01

Input integrity

Genome build, chromosome mapping, coordinates, REF/ALT alleles, duplicates, missingness, and sequence context.

02

Inference provenance

Model revision, upstream code, packages, parameters, device, inputs, outputs, runtime, and hashes.

03

Population orientation

Separate raw REF-to-ALT model scores from population minor-vs-major scores so the biological comparison is explicit.

04

Biological concordance

Evaluate model concordance with allele frequency, conservation, and genomic context, while testing LD sensitivity and summarizing population structure.

v0.3.0 — Evolutionary evidence

v0.3.0 · Released

v0.3.0 added the ability to integrate frozen model outputs with genomic annotations and LD-aware descriptive checks. It integrates population-oriented GPN and PlantCAD scores with evolutionary and genomic evidence for 10,000 real Arabidopsis thaliana population variants selected using a deterministic procedure. The release is organized around a frozen 10,000 × 39 annotated master table, with exclusive genomic-context annotations, signed site-oriented PhyloP conservation, fixed physical-bin and LD-sensitivity analyses, genotype-quality summaries, and UMAP population-structure summaries.

The v0.3 release assets are frozen and hash-verified. Its primary population score is log P(minor allele) − log P(major allele). Raw model scores retain log P(ALT) − log P(REF). PhyloP is site-oriented, not allele-oriented, so its sign is not treated as an allele preference.

Validated descriptive results

  • GPN–PlantCAD: Spearman ρ = 0.6525, Pearson r = 0.6331, n = 10,000.
  • GPN–PhyloP: Spearman ρ = −0.1876, n = 9,453.
  • GPN–PlantCAD remains approximately 0.6523–0.6534 across released LD profiles.
  • Context-stratified GPN–PlantCAD Spearman correlations range from 0.5171 in coding CDS to 0.7349 in intergenic variants.

The sample-quality summaries contain 1,135 samples in the sample-quality table, 1,093 samples in the primary call-rate set, 996 samples in the strict set, and geographic metadata for 1,131 samples.

These are descriptive associations. They do not show that either model directly measures fitness, selection, causality, or pathogenicity. v0.3.0 claims no hypothesis-test p-values.

v0.2.0 — Population-aware benchmark

v0.2.0 · Released

v0.2.0 · Released · Population-aware benchmark

10,000 real Arabidopsis thaliana variants

v0.2.0 added deterministic population sampling, exact reference validation and explicit minor-versus-major score orientation. It uses deterministically selected biallelic SNPs from the 1001 Genomes Project, validates every REF allele against TAIR10.1, combines population summaries with reproducible GPN Brassicales scores, and evaluates the relationship between minor-allele frequency and model score.

−0.132rare-vs-common rank-biserial effect

The primary population-oriented score is log P(minor) − log P(major). Negative values mean that GPN assigns lower sequence likelihood to the population minor allele than to the major allele.

For variants in which ALT is the minor allele, the raw score log P(ALT) − log P(REF) already has the required orientation. For the 246 ALT-major variants, the sign is reversed. This transformation makes the population comparison explicit; it does not create the observed genome-wide association.

Main result

Across the 10,000-variant benchmark:

  • Spearman ρ = 0.0611 between MAF and the GPN minor-vs-major score;
  • chromosome-stratified Monte Carlo p = 1 / 10,001;
  • rare variants have median score −0.3485;
  • common variants have median score −0.1562;
  • rare versus common rank-biserial effect = −0.1322;
  • bootstrap 95% CI = [−0.1665, −0.0973].

The result is therefore weak but reproducible concordance, not strong predictive separation. The distributions overlap extensively.

Interpretation boundary: this result is not evidence that GPN directly predicts natural selection. Population demography, structure, linkage disequilibrium, ascertainment, allele age, and other evolutionary processes may contribute. The chromosome-stratified permutation preserves chromosome membership but does not explicitly model local LD.

Robustness

The positive association remains under stricter data filters:

Analysis n Spearman ρ
All variants 10,000 0.0611
Call rate ≥ 0.95 6,761 0.0581
MAC ≥ 5 5,057 0.0876
Call rate ≥ 0.95 and MAC ≥ 5 3,279 0.1002

The association is also positive separately on chromosomes 1–5 and remains positive after excluding each chromosome in turn. This supports the conclusion that the genome-wide direction is not being driven by a single chromosome.

From model score to biological evidence

→
ModelSequence scoreExplicit score semantics
→
PopulationMAF + orientationMinor versus major allele

The central design principle is separation of concerns. Model scoring, reference validation, population orientation, statistical evaluation, and biological interpretation remain distinct steps. This makes failure modes inspectable and helps prevent a model score from being promoted directly into a biological claim.

Version history and roadmap

The learning path is chronological: v0.1 verified a 100-variant fixture end to end; v0.2 made the reference and population allele comparison explicit; v0.3 added evolutionary evidence and LD checks; v0.4 tests which linked SNPs a researcher would follow up. v0.5 is extending that evaluation to gene-expression prediction and paired regulatory effects while preserving model-specific score meaning and a complete reproduction record. v0.4 remains the latest release; v0.5 is still development, not a completed benchmark.
